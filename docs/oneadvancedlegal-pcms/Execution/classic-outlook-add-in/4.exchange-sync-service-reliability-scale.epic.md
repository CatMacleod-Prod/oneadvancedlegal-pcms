# Exchange Sync Service Reliability & Scale

## Strategic Context
The Exchange Sync Service acts as the critical backend ingestion pipeline processing sent emails, notifications, and metadata attachments from Microsoft Exchange into PCMS. Supporting Classic Outlook compose filing at scale requires enterprise-grade webhook management, subscription resilience, and high-throughput payload processing without message drop or lag.

## Success Criteria
- Exchange Sync Service reliably handles notification processing, subscription management, and payload creation for Classic Outlook emails at scale.
- 100% of Exchange Sync Service functional and performance test suites pass under simulated load of 100+ concurrent active fee earners.
- Sub-second average ingestion latency from Exchange message dispatch to PCMS matter document indexing.
- Zero dropped messages or orphaned metadata payloads during Exchange webhook throttling or intermittent outages.

## Scope

### In Scope
- Microsoft Graph and Exchange webhook notification listener and renewal orchestration.
- Subscription lifecycle management (creation, refresh, teardown, and recovery).
- Payload extraction, single-value extended property decoding, and PCMS matter filing pipeline.
- End-to-end performance and load testing suites simulating enterprise practice volume.

### Out of Scope
- On-premises Exchange Server 2016/2019 direct MAPI protocol listeners (Exchange Online / M365 only).
- Client-side UI rendering within Outlook.

## Acceptance Criteria
WHEN Microsoft Exchange emits a sent item notification for a stamped email, the Exchange Sync Service SHALL process the notification and queue the payload within 500ms.

WHEN processing the sent item payload, the Exchange Sync Service SHALL extract the single-value extended property metadata and create the corresponding PCMS document record.

WHERE Exchange notification throttling or network backpressure occurs, the Exchange Sync Service SHALL apply exponential backoff and retry without dropping messages.

IF an email payload contains attachments, THEN the Exchange Sync Service SHALL extract, index, and associate each attachment with the parent matter file.

WHEN performance testing is executed with 100+ concurrent active sessions, the Exchange Sync Service SHALL maintain a p95 processing time under 1.5 seconds.

## Business Rules
- Existing document storage flows in Outlook Service API and Product API must remain invariant and untouched.
- Subscriptions must be automatically renewed before their expiration threshold to prevent notification gaps.

## Dependencies
- Microsoft Graph Webhook Subscriptions and Azure Event Grid / Service Bus messaging infrastructure.
- PCMS Document Storage & Indexing Service APIs.
