# Classic Outlook Compose & Metadata Filing

## Strategic Context
Fee earners frequently draft new client correspondence from Classic Outlook (Win32) desktop clients. Inability to assign matter metadata during email composition forces retrospective post-send filing, causing compliance delays and fee-earner context switching. This epic enables end-to-end compose-time filing in Classic Outlook using single-value extended properties synced via the Exchange Sync Service into PCMS without altering underlying document storage APIs.

## Success Criteria
- New Compose Email filing works end-to-end in Classic Outlook: PCMS resource selection, extended property written at save, and document saved correctly after send via Exchange Sync Service.
- Extended property write operations complete within 200ms of user selection.
- Zero changes required to existing document storage flow in Outlook Service API or Product API.
- Zero email send delays or client lockups during extended property persistence.

## Scope

### In Scope
- Compose-mode task pane integration for Classic Outlook (Win32).
- PCMS Matter and Client entity search and association within compose view.
- Single-value extended property stamping on draft item before send (`customProperty` / MAPI named property).
- Integration with Exchange Sync Service to extract metadata and ingest email into PCMS post-send.

### Out of Scope
- Modification of existing PCMS document storage backend schemas or storage APIs.
- Inline attachment redaction inside the compose window.

## Acceptance Criteria
WHEN a fee earner opens a new email compose window in Classic Outlook, the Add-In Task Pane SHALL provide PCMS matter search and selection.

WHEN the fee earner selects a target matter and clicks Save/Assign, the Add-In SHALL write the PCMS Matter GUID as a single-value extended property on the draft item within 200ms.

WHEN the user sends the email, the Exchange Sync Service SHALL read the extended property from the sent item and file the email and attachments directly into the corresponding PCMS matter file.

IF network connectivity is interrupted during compose metadata selection, THEN the Add-In SHALL retain local state and retry property stamping upon reconnection before send.

## Business Rules
- Existing document storage flows in Outlook Service API and Product API must remain unchanged; payload format must adhere to existing ingestion contracts.
- Sent emails without matter metadata must not be ingested by the Exchange Sync Service.

## Dependencies
- Exchange Sync Service notification endpoint operational.
- Outlook Service API ingest endpoint available.
