# Automated Completion Monies and Postings

## Strategic Context
Completion day in residential conveyancing involves high-value, time-sensitive financial movements across client and office bank accounts. Cashier teams currently face heavy administrative burdens manually keying receipts, transfers, and redemption disbursements into accounting ledgers. Automating completion postings via API significantly reduces completion-day bottlenecks while enforcing strict auditability and SRA compliance rules.

## Success Criteria
- Deployment of automated accounting posting endpoints across Sprint 15 (contingent upon decision D-04 approval).
- Full compliance and authorization validation ensuring no posting can be executed without requisite approval tiers.
- Zero duplicate ledger postings achieved through strict idempotency mechanisms.

## Scope

### In Scope
- Client receipt posting POST for recording incoming client completion funds.
- Client-to-office transfer posting POST with digital multi-tier authorization.
- Completion payment / disbursement posting POST for outgoing mortgage redemptions and partner fees.
- Idempotency and audit log integration across all financial posting routes.

### Out of Scope
- Full general ledger restructuring (governed by core PCMS Legal Accounts module).
- External Open Banking payment initiation (BACS/CHAPS execution).
- Workflows if decision D-04 is rejected (in which case capacity reallocates to integration hardening).

## Acceptance Criteria
WHEN POST /v1/matters/{matterId}/postings/client-receipt is invoked with verified receipt details, the Accounting API SHALL create the corresponding client ledger credit entry and update live account balances.

WHEN a client-to-office transfer is requested via POST /v1/matters/{matterId}/postings/client-to-office-transfer, the Accounting API SHALL validate sign-off permissions, debit the client ledger, and credit the office ledger.

WHEN an outgoing completion payment is posted via POST /v1/matters/{matterId}/postings/payment, the Accounting API SHALL log the payment transaction, update matter disbursements, and adjust net balances.

WHERE duplicate posting requests are submitted with identical idempotency keys, the Accounting API SHALL return the existing posting confirmation without creating duplicate ledger entries.

IF a posting request fails authorization or exceeds permitted thresholds, THEN the Accounting API SHALL reject the transaction with an auditable error code and alert compliance officers.

## Business Rules
- All postings must strictly adhere to Solicitors Regulation Authority (SRA) Accounts Rules (no client account deficits permitted).
- Client-to-office transfers require verified billed invoices or approved disbursement recovery records.
- Posting operations must be immutable and record full audit metadata (user ID, timestamp, matter ID, amount).

## Dependencies
- Core PCMS Legal Accounts ledger module and authorization service.
- Common Conveyancing API Foundation (ConveyFinance entity and idempotency middleware).
- Compliance sign-off and formal approval of Product Decision D-04.

## Open Questions
