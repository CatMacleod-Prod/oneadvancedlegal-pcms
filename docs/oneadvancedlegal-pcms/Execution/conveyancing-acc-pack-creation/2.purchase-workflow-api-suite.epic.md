# Purchase Workflow API Suite

## Strategic Context
Purchase transactions represent the highest volume and complexity in conveyancing practices, requiring extensive document generation, statutory search management, funding breakdowns, and stamp duty calculations. Currently, fee earners must leave the workflow to access external desktop tools for Laserforms, SDLT calculations, and folder scaffolding. Providing a unified Purchase API suite automates these interactions, accelerating matter velocity and eliminating manual re-keying.

## Success Criteria
- Delivery and deployment of all 27 confirmed Purchase-specific Tier 3 endpoints across Sprints 6–10.
- End-to-end programmatic generation, field retrieval, and submission of Laserforms and Hub/SDLT forms.
- Real-time SDLT and Welsh LTT calculation returning accurate liability breakdowns based on transaction variables.
- Automated creation of structured matter DMS folder hierarchies from predefined templates.

## Scope

### In Scope
- Legal forms (Laserforms) catalogue GET, form fields GET, submit POST, and matter forms GET.
- Key dates GET and PUT integrated with reference data lookup types.
- Searches GET, search result PUT, and POST search order placement.
- Milestones GET and PUT for workflow stage tracking.
- Matter account balances GET (client and office ledgers).
- Funding sources GET, POST (by funding type), and PATCH for mortgage, equity, and gift tracking.
- Contact-role check GET for automated BPMN gateway evaluations (e.g. lender attached validation).
- DMS folder creation POST and folder structure generation from templates POST.
- Hub forms catalogue GET, form fields GET, submission POST, and PATCH update.
- Stamp Duty Land Tax (SDLT) and Land Transaction Tax (LTT) tax calculation POST.

### Out of Scope
- Direct submission to HMRC / Welsh Revenue Authority APIs without Laserform Hub (deferred to Phase 5).
- Advanced enquiry register management (governed by decision D-01 in Phase 5).
- Multi-provider search adapter plugins beyond the approved provider model (decision D-14).

## Acceptance Criteria
WHEN a client submits a form via POST /v1/matters/{matterId}/legal-forms or /hub-forms, the Purchase API Suite SHALL validate required fields and persist the form instance against the matter record idempotently.

WHEN POST /v1/matters/{matterId}/conveyancing/tax-calculation is invoked with purchase price, transaction type, and buyer classification, the Purchase API Suite SHALL calculate and return the exact SDLT or LTT liability breakdown.

WHEN POST /v1/matters/{matterId}/folders/from-template is called with a valid template identifier, the Purchase API Suite SHALL provision the entire folder directory structure in the DMS for the matter.

WHERE search orders are created via POST /v1/matters/{matterId}/searches, the Purchase API Suite SHALL validate searchTypeId against active search types and attach the order to the matter.

IF a contact-role check is requested via GET /v1/matters/{matterId}/contact-role-check, THEN the Purchase API Suite SHALL return whether the specified role (e.g., Lender) is associated with the matter.

## Business Rules
- Tax calculation logic must support residential higher rates (additional dwellings) and first-time buyer relief rules.
- Funding sources PATCH must enforce consistency so that total funding matches or accounts for the gross purchase price.
- Search result updates must verify that the searchId strictly belongs to the specified matterId.

## Dependencies
- Common Conveyancing API Foundation (property, finance, idempotency middleware, and controller scaffolding).
- Laserform engine and DMS service connectivity.
