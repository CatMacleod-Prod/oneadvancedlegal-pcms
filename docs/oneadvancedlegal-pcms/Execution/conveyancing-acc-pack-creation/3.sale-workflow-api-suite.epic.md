# Sale Workflow API Suite

## Strategic Context
Sale transactions require rigorous compliance checks, title defect tracking, apportionment calculations, and pre-exchange/pre-completion gateway validations. Currently, conveyancers must manually evaluate readiness checklists and perform identity verifications across disconnected portals. Exposing dedicated Sale workflow endpoints enables automated readiness gates, programmatic apportionment tracking, and seamless compliance integrations.

## Success Criteria
- Deployment of confirmed Sale endpoints across Sprints 11–14 covering AML, title issues, apportionments, checklists, and identity verification.
- Automated evaluation of pre-exchange and pre-completion checklists returning structured pass/fail readiness data.
- Successful integration with Lender Exchange and Thirdfort for automated conveyancer and client AML verification.

## Scope

### In Scope
- AML reference and status update PUT (S1).
- Completion confirm POST triggering downstream document generation and milestone updates (S2).
- Title defects and issues recording POST (S3).
- Estate agent fee and invoice tracking POST (S4).
- Pro-rata apportionments calculation and recording POST (S5).
- Key release authorization and confirmation POST (S6).
- Automated completion readiness checklist GET (S7).
- Automated exchange readiness checklist GET (S8).
- Conveyancer identity verification POST integrating with Lender Exchange (S9).
- Thirdfort AML verification integration POST (S10).

### Out of Scope
- Automated cashier ledger postings for sale proceeds (deferred to Completion Postings Epic).
- Full custom enquiry management register (deferred to Phase 5).

## Acceptance Criteria
WHEN GET /v1/matters/{matterId}/exchange/checklist or /completion/checklist is requested, the Sale API Suite SHALL evaluate property, financial, AML, and documentation prerequisites and return structured pass/fail statuses for each check.

WHEN POST /v1/matters/{matterId}/conveyancer-identity/verify is called with firm credentials, the Sale API Suite SHALL submit an identity check to Lender Exchange and return the verification status.

WHEN pro-rata apportionments are submitted via POST /v1/matters/{matterId}/apportionments, the Sale API Suite SHALL calculate balances based on completion date and persist the ledger adjustments against the matter.

WHERE completion confirmation is submitted via POST /v1/matters/{matterId}/completion/confirm, the Sale API Suite SHALL record completion status and dispatch completion notifications idempotently.

IF physical key handover is authorized via POST /v1/matters/{matterId}/completion/key-release, THEN the Sale API Suite SHALL generate an auditable key release reference and update matter state.

## Business Rules
- Exchange and completion checklists must evaluate all critical blockers (unverified AML, outstanding title issues, unallocated funds) before returning an overall 'Pass'.
- Apportionment calculations must support daily pro-rata adjustments for ground rent, service charges, and council taxes based on the specified completion date.
- Conveyancer identity verification must operate asynchronously with polling support for external verification results.

## Dependencies
- Common Conveyancing API Foundation (property, finance, and completion endpoints).
- Third-party onboarding and API agreements for Lender Exchange and Thirdfort.
