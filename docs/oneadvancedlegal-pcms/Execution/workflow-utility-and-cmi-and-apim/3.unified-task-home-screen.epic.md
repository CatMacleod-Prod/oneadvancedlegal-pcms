# Unified Task Home Screen

## Strategic Context
Fee earners and operational staff currently navigate multiple disconnected screens and queues to manage daily responsibilities, causing context-switching overhead and missed deadlines. This epic delivers a consolidated Task Home Screen UI that centralizes all actionable work items into a single view—including directly assigned general system tasks, tasks from workflows owned by the user, and tasks allocated to user-associated functional groups. Providing real-time aggregation, sorting, and priority filtering eliminates operational blind spots and ensures compliant, timely execution across all active matters.

## Success Criteria
- Sub-second UI load and filter latency for task aggregation across 100+ concurrent active users.
- 100% visibility of assigned tasks across three assignment scopes: direct user assignment, owned workflow tasks, and user group memberships.
- Reduction of daily administrative navigation time by consolidating disparate workflow and ad-hoc task queues into a single home screen workspace.

## Scope

### In Scope
- Dedicated Task Home Screen UI supporting tabular and card views for unified task tracking.
- Unified task aggregation across Flowable workflow engine tasks and core PCMS general/ad-hoc system tasks.
- Multi-dimensional assignment filtering: "Assigned to Me", "My Owned Workflows", and "My Groups".
- Filter, search, and sorting controls for priority badges (P1/P2/P3/Urgent), due date, matter reference, client name, and task status.
- Direct quick-action controls allowing inline status transitions, task completion, reassignment, and matter detail deep-linking.

### Out of Scope
- Workflow template authoring and BPMN modeling canvas (managed within the Workflow Admin module).
- Automated AI task execution and autonomous bot completion (deferred to future agentic workflow releases).
- Third-party calendar bi-directional synchronization (e.g., Google Calendar / Apple Calendar).

## Acceptance Criteria
WHEN a user navigates to the Task Home Screen, the Task Management UI SHALL retrieve and display all active tasks matching the user's direct assignment, owned workflow instances, and associated group memberships.

WHERE a task is associated with an active BPMN workflow instance, the Task Management UI SHALL display the workflow progress state, parent matter reference, and step-specific completion action button.

WHERE a task is a non-workflow general system task, the Task Management UI SHALL display the task description, target due date, creator, and standard completion checkbox.

WHEN a user applies filter criteria by assignment scope ("Assigned to Me", "My Owned Workflows", "My Groups"), the Task Management UI SHALL update the displayed task list within 500 milliseconds without requiring a full page refresh.

IF a task due date is past the current system timestamp and the task status is not "Done", THEN the Task Management UI SHALL render a visual overdue badge with high-contrast priority styling.

WHEN a user selects a task row, the Task Management UI SHALL open the corresponding matter timeline or workflow execution modal with context preserved.

## Business Rules
- Group task assignment resolution must inherit all active role-based access control (RBAC) groups and practice department affiliations assigned to the user profile in PCMS.
- Completed and cancelled tasks are hidden from the default active view but remain accessible via an explicit historical status filter.
- Priority levels are standardized as Critical (P1), High (P2), Medium (P3), and Low (P4), with visual badges reflecting standard design system tokens.
- Workflow task actions must respect underlying Flowable BPMN candidate user and candidate group permissions before enabling interaction controls.

## Dependencies
- PCMS Task Query REST API endpoints supporting aggregated multi-scope filtering and pagination.
- Flowable BPMN workflow engine task listener and subscription endpoints.
- Role-Based Access Control (RBAC) user group membership directory service.

## Open Questions
- What default sorting sequence should be applied on initial load (e.g., chronological due date vs. priority weighting)?
- Should group tasks claimed by one member remain visible in read-only mode to other group members or immediately disappear from peer lists?
