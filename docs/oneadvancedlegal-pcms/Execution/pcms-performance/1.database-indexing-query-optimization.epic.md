# Database Indexing & Query Optimization

## Strategic Context
Mid-market law practices operating at 50 to 100+ concurrent users experience significant database latency, query deadlocks, and slow matter ledger lookups during peak operational windows. Inefficient indexing across high-volume relational tables—such as matter timelines, audit logs, and client accounting records—causes query queues that degrade the entire PCMS interface. Optimizing database schema indexes and query execution plans eliminates these bottlenecks, reducing peak transaction latency by over 60% and ensuring instant data availability for fee earners.

## Success Criteria
- 95th percentile query latency on matter search and ledger lookups reduced to under 200ms under 100+ concurrent user load.
- Database deadlock occurrences eliminated during concurrent month-end billing and bulk transaction processing.

## Scope

### In Scope
- Analysis of slow query logs and query execution plans across all core matter and financial tables.
- Addition of composite and partial indexes for high-cardinality queries and matter timeline filtering.
- Refactoring of N+1 queries and inefficient ORM joins across case management APIs.

### Out of Scope
- Full database engine migration or cross-region database sharding (deferred to future infrastructure phase).

## Acceptance Criteria
WHEN a fee earner executes a matter search query across 100,000+ records, the Database Engine SHALL return indexed query results in under 200ms.

WHERE multi-column filtering is applied to matter ledgers, the Query Planner SHALL utilize composite indexes without performing full-table scans.

IF concurrent write operations occur on the same matter timeline, the Database Engine SHALL execute non-blocking row-level transactions without transaction deadlocks.

## Business Rules
- All new database schema migrations must include automated query performance benchmarking in CI before deployment.
- Indexing strategies must not increase write latency by more than 5% on core transactional records.

## Dependencies
- Production query telemetry and slow-query logs from PCMS staging and production environments.

## Open Questions
- Are there legacy reporting queries that require read-replica offloading rather than index optimization alone?
