# SharePoint Document Streaming & Bundle Provisioning

## Strategic Context
PCMS stores matter documents within SharePoint and OneDrive rather than local disk storage. Downloading multi-gigabyte document sets to web server disks creates storage exhaustion risks, privacy compliance exposure, and latency bottlenecks. Direct memory-efficient streaming from Microsoft Graph API to the BundleDocs upload endpoint provides sub-second throughput with zero disk footprints.

## Success Criteria
- Multi-document direct binary streaming from SharePoint/OneDrive directly to BundleDocs `POST /api/v1/documents`.
- Zero temporary file creation on PCMS hosting servers during bundling operations.
- Successful transfer of individual document payloads up to 50MB.

## Scope

### In Scope
- Integration with Microsoft Graph API client to retrieve document read streams.
- Multipart/form-data upload pipeline streaming file bytes into BundleDocs `POST /api/v1/documents`.
- Progress tracking loop querying `GET /api/v1/events/{context}`.
- Payload validation for document types (.pdf, .docx, .msg, .xlsx, .jpg).

### Out of Scope
- Chunked transfer fallback for individual files exceeding 50MB (deferred to Phase 2).
- Automatic OCR or client-side conversion prior to streaming (handled natively in BundleDocs).

## Acceptance Criteria
WHEN multiple documents are queued for bundling, the DocumentStreamingService SHALL retrieve each file stream sequentially via Microsoft Graph API and stream it directly to BundleDocs without persisting bytes to disk.

WHEN uploading a document stream, the DocumentStreamingService SHALL construct a `multipart/form-data` payload containing `file`, `PartitionKey`, `ForeignKey`, and `ParentRowKey`.

WHERE a file upload completes, the DocumentStreamingService SHALL poll `GET /api/v1/events/{bundleRowKey}` to verify processing status before proceeding to subsequent documents.

IF an individual file stream exceeds 50MB, THEN the DocumentStreamingService SHALL abort the transfer and return a descriptive payload size error to the caller.

IF a stream interruption occurs during transfer, THEN the DocumentStreamingService SHALL retry the specific file upload up to 2 times before failing the sequence.

## Business Rules
- Total memory buffer per active upload stream must not exceed 8MB.
- Document original filenames and extensions must be preserved exactly as indexed in PCMS.
- Streaming operations must respect user document permission ACLs from SharePoint.

## Dependencies
- Microsoft Graph API Drive Item endpoints.
- BundleDocs Cloud API Document upload endpoint (`/api/v1/documents`).
