# Database Stored Procedure Optimization & Hot-Path Tuning

## Strategic Context
Core transaction paths, specifically client/matter creation and lockup calculation procedures, experience lock contention and thread starvation under high concurrency. Removing blocking `.Result` invocations on hot paths and refactoring top-offending stored procedures is critical to unlocking reliable sub-3-second transaction times at 350 active users.

## Success Criteria
- Client creation (`CCCM_10_CreateNewClient`) and matter creation (`CCCM_12_CreateNewMatter`) maintain P95 ≤ 2 seconds under 350-user concurrent load.
- Removal of all 6 blocking synchronous `.Result` calls on hot transaction paths.
- `usp_Dash_Lockup` refactored from correlated cursor scans to set-based logic, reducing logical reads by ≥ 80%.

## Scope

### In Scope
- Query Store cost ranking spike to isolate top-10 worst-performing production procedures (SP-02).
- Cost-ranked rewrite of top offenders including `usp_Dash_Lockup` (SP-03).
- Offloading administrative and batch stored procedures from the interactive request path (SP-04).
- Production deployment reconciliation and verification for `Next_Client` lock contention fix (SP-05).
- Conversion of 6 named hot-path blocking `.Result` calls to non-blocking async operations (SP-06).
- Permission-check cost optimization for `CCCM_12_CreateNewMatter` (SP-07).

### Out of Scope
- Complete database schema overhaul or microservice database partitioning.
- Non-hot-path legacy background SQL migrations.

## Acceptance Criteria
WHEN a fee earner creates a new client or matter, the Database Service SHALL allocate reference sequences atomically without holding locks on the parent table.

WHEN document generation and editing orchestrators execute file operations, the Application Layer SHALL await I/O calls asynchronously without blocking thread-pool workers.

IF an administrative batch procedure is triggered by an operational user, THEN the System SHALL queue the execution asynchronously off the interactive database path.

## Business Rules
- Reference generation must remain strictly sequential without gaps across concurrent users.
- Stored procedure rewrites must maintain exact output parity with existing regression suites.

## Dependencies
- Production Query Store access to capture accurate execution plan baselines.
- Architecture approval for moving administrative operations to async execution (GATE-04).
