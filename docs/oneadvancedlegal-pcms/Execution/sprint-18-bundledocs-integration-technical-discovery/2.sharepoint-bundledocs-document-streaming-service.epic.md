# SharePoint to BundleDocs Document Streaming Service

## Strategic Context
Executes the technical discovery spike (LSS-2374) to investigate PCMS document streaming architecture, Bundledocs REST API payload contracts, and storage integration points. Evaluates real request/response schemas for `/create-bundle`, `/template`, `/tree`, `/upload`, `/events`, `/receipts`, and `/download` endpoints to de-risk high-volume matter document transfers.

## Scope
### In Scope
- Capturing real request and response payloads from Bundledocs sandbox endpoints (`create-bundle`, `template`, `tree`, `upload`, `download`).
- Testing parallel document upload feasibility from SharePoint / PCMS storage to Bundledocs.
- Determining exact PCMS trigger points, context data availability, and microservice hosting architecture.
- Designing storage mechanisms and linking metadata for completed bundle PDFs within PCMS matter histories.
- Evaluating the `Bundledocs.net 0.7.0` NuGet package for SDK capabilities and identifying missing feature gaps.

### Out of Scope
- Building end-to-end production streaming worker pipelines.
- UI components for document selection.
- Full PDF indexing and OCR processing engine.

## Success Criteria
- Concrete JSON request/response samples captured for all primary Bundledocs endpoints in the technical findings note.
- Multi-document parallel streaming benchmark completed and maximum concurrent upload throughput determined.
- Documented architectural blueprint defining where the integration logic lives in PCMS and how returned PDFs are stored.
- Feature gap analysis of the `Bundledocs.net 0.7.0` SDK completed with vendor feature requests drafted if needed.

## Acceptance Criteria
- The technical lead SHALL document sample JSON payloads for bundle creation, folder/tree structure, and document upload against the Bundledocs sandbox.
- The technical lead SHALL test and document whether multi-file uploads can be parallelized and define recommended chunk sizes / concurrency limits.
- The technical lead SHALL document the precise PCMS trigger point and define all data models available at invocation time.
- The technical lead SHALL define the storage location, naming convention, and case-linking mechanism for downloaded court bundle PDFs in PCMS.

## Business Rules
- BR-1: Spike testing must not store unencrypted customer files in temporary local storage during upload tests.
- BR-2: Parallel streaming tests must evaluate and adhere to Bundledocs sandbox rate limits.
- BR-3: Storage blueprints must ensure strict data isolation and audit tracking per PCMS matter.

## Dependencies
- Epic 1: BundleDocs OAuth2 Authentication and Tenant Configuration.
- Bundledocs OpenAPI specification (`https://app.bundledocs.com/swagger/v1/swagger.json`).
- `Bundledocs.net 0.7.0` NuGet package.

## Open Questions
- What are the single-file and batch upload size limitations in the Bundledocs REST API?
- Does Bundledocs provide webhooks for completed builds, or is polling required?
