# BundleDocs OAuth2 Authentication and Tenant Configuration

## Strategic Context
Executes the technical discovery spike (LSS-2374) to investigate Bundledocs API authentication mechanisms, bearer token lifecycles, and tenant credential isolation. Validates the OAuth2 client credentials flow against the Bundledocs sandbox (`https://app.bundledocs.com/swagger/v1/swagger.json`) and evaluates the `Bundledocs.net 0.7.0` SDK to establish a secure foundation for PCMS integration.

## Scope
### In Scope
- Verification of developer account elevation and sandbox API access.
- Investigation of OAuth2 token acquisition, token expiry semantics, and automatic refresh intervals.
- Validation of authentication failure responses (HTTP 401/403) and token invalidation.
- Architectural evaluation of where integration credentials and per-tenant configs should live in PCMS.
- Sandbox credential rotation and revocation procedures.

### Out of Scope
- Production tenant administration UI implementation.
- User-level / fee-earner OAuth2 delegation.
- Automated CI/CD secret deployment pipelines.

## Success Criteria
- Written technical findings document delivered detailing exact OAuth2 token lifecycle, TTL, and refresh behaviour.
- Direct test calls executed against Bundledocs sandbox using client credentials.
- Security confirmation of in-memory bearer token handling and sandbox credential isolation.
- Evaluation of `.NET SDK (Bundledocs.net 0.7.0)` authentication support completed.

## Acceptance Criteria
- The technical lead SHALL document the exact endpoint URL, request format, and response payload for Bundledocs OAuth2 bearer token acquisition.
- The technical lead SHALL document token expiration parameters and recommend the PCMS token refresh strategy (e.g. proactive refresh at <5m remaining).
- The technical lead SHALL verify that sandbox credentials can be revoked and rotated without affecting production PCMS services.
- The technical lead SHALL document any limitations or missing features in the `Bundledocs.net 0.7.0` SDK regarding authentication.

## Business Rules
- BR-1: Sandbox credentials used during the spike must be sandbox-only, not production credentials, and rotated/revoked once the spike concludes.
- BR-2: Secrets and bearer tokens must never be logged or persisted in plain text during spike test execution.
- BR-3: Tenant isolation architecture must prevent cross-tenant credential exposure.

## Dependencies
- Creation and elevation of Bundledocs developer account.
- Access to Bundledocs Swagger definition (`https://app.bundledocs.com/swagger/v1/swagger.json`).
- Access to `Bundledocs.net 0.7.0` NuGet package.

## Open Questions
- What is the default token expiry window returned by Bundledocs token endpoints?
- Does Bundledocs enforce IP allowlisting or client certificate requirements on token endpoints?
