# Architecture Document

## System Overview

### Purpose
The Document Management & Integration Service is a high-throughput, cloud-native microservice responsible for legal document lifecycle management, Microsoft Graph API / SharePoint Online integrations, full-text indexing, dynamic precedent assembly, and automated electronic court bundle generation across the United Kingdom. Operating in tandem with the PCMS Core Application, it serves mid-market and large legal practices (50 to 500+ staff, supporting 100+ to 450 concurrent fee earners) across England, Wales, and Scotland. The service handles direct document ingestion from both Classic Win32 and New Outlook add-ins, multi-party Office 365 co-authoring orchestration, dynamic legal precedent drafting, and asynchronous CPU-intensive court bundle compilation strictly compliant with HMCTS / Ministry of Justice (MoJ), Scottish Courts and Tribunals Service (SCTS), and Legal Aid Agency (LAA) Crown Court Litigators' Graduated Fee Scheme (LGFS) prosecution evidence (PPE) standards, while enforcing dual-jurisdiction Solicitors Regulation Authority (SRA) and Law Society of Scotland data governance mandates. In addition, the service provides pluggable microservice hooks and telemetry ingestion to support rapid quarterly enhancement cycles delivering continuous email handling and document service optimizations.

### Architecture Style
Event-driven Microservice with Asynchronous Task Workers (Containerized ASP.NET Core API service coupled with asynchronous background worker nodes and resilient message brokers).

### Key Design Principles
- **Decoupled Document Binary & Metadata Storage**: Persists logical document pointers, matter classifications, jurisdiction flags, checksums, and version tags in PostgreSQL while streaming raw file binaries directly to customer SharePoint Online document libraries via Microsoft Graph API.
- **Dynamic Precedent Assembly**: Provides high-performance template tokenization and OpenXML data-binding pipelines to assemble jurisdiction-compliant legal precedents (pleadings, missives, contracts) populated directly from PCMS matter metadata.
- **Crown Court LGFS & PPE Evidence Processing**: Analyzes, verifies, and indexes Pages of Prosecution Evidence (PPE) and court documentation for automated tariff calculations under LAA Crown Court fee schemes.
- **Dual-Jurisdiction Regulatory Governance**: Enforces automated retention schedules, immutable audit trails, and ethical wall policies configured dynamically for both SRA and Law Society of Scotland compliance frameworks.
- **Dual Outlook Environment Ingestion**: Provides unified, high-speed streaming ingestion endpoints optimized for both Classic Outlook (Win32 / VSTO) and New Outlook for Windows / Web (Office.js) clients with predictive filing telemetry.
- **Continuous Quarterly Delighter Microservices**: Modular API hooks and lightweight operational processing workers enabling rapid deployment of email predictive filters, attachment tools, and productivity micro-features without breaking core document schemas.
- **Resilient API Integration**: Implements Polly retry policies, distributed token caching, exponential backoff, and circuit breakers to handle Microsoft Graph API rate limits (HTTP 429) under 100+ concurrent user loads.
- **Asynchronous Heavy Processing**: Completely isolates CPU- and memory-intensive court bundle collation, OCR text extraction, Bates stamping, and PDF/A-1b/2b conversion from interactive API request threads.
- **Zero-Trust Access Delegation**: Evaluates matter-level ethical walls and fee-earner permissions in real time before issuing short-lived Graph API upload/download session tokens.

## System Context

### External Systems
- **Microsoft Graph API & SharePoint Online**: Primary external document repository used for automated matter workspace folder provisioning, binary persistence, version retrieval, and Office 365 co-authoring sessions.
- **PCMS Core Application**: Authoritative practice and case management system providing matter context, fee-earner identity, ethical wall rules, public funding metrics (LGFS/LAA/SLAB), and dual-jurisdiction practice metadata.
- **Judicial Submission Portals (HMCTS & SCTS)**: Electronic filing gateways for England & Wales (HMCTS e-Filing) and Scotland (Scottish Courts and Tribunals Service / SCTS Civil Online) receiving compiled, paginated electronic bundles.
- **Legal Aid Agency (LAA) Digital Claim Portals**: Public funding submission gateways requiring verified Pages of Prosecution Evidence (PPE) counts and itemized document schedules for Crown Court fee recovery.
- **OneAdvanced Identity Platform & Entra ID**: Identity providers managing Single Sign-On (SSO), OpenID Connect (OIDC), OAuth 2.0 client credentials, and Microsoft Graph On-Behalf-Of (OBO) token exchanges.
- **Azure Service Bus / AWS SQS**: Enterprise message broker for asynchronous dispatch and reliable queueing of high-volume document indexing, precedent assembly, and court bundle compilation jobs.

### Users & Actors
- **Solicitors, Advocates & Fee Earners**: Legal staff uploading matter filings, initiating Word/Excel co-authoring sessions, running dynamic precedent assembly, and filing correspondence via Classic and New Outlook.
- **Criminal Litigators & Legal Aid Specialists**: Fee earners verifying Pages of Prosecution Evidence (PPE) counts and generating compliant documentation bundles for Crown Court LGFS claims.
- **Paralegals & Legal Secretaries**: High-volume power users structuring court bundles, configuring Bates numbering schemes, initiating OCR jobs, and generating closing bibles.
- **Compliance Officers (COLP, COFA & Scottish Cashroom Partners)**: Governance officers monitoring document retention schedules, legal hold policies, and Subject Access Requests (SARs) across jurisdictions.
- **PCMS Core Background Dispatcher**: Internal automated dispatcher initiating automated matter workspace provisioning, precedent assembly triggers, and milestone document workflows.

### Components
#### Graph API Integration Gateway
- **Responsibility**: Manages Graph API OAuth2 token lifecycles, throttled request queues, webhook event listeners, matter folder provisioning, and chunked upload session creation for files exceeding 4MB.
- **Technology**: .NET 8 / C# (ASP.NET Core Web API) with Polly resiliency framework and Redis token caching.
- **Interfaces**: RESTful JSON APIs for PCMS Core and Microsoft Graph REST endpoints.

#### Document Metadata & Version Registry
- **Responsibility**: Stores and indexes logical document references, SharePoint `driveItem` identifiers, SHA-256 checksums, version histories, ethical wall locks, and jurisdiction tags (England & Wales vs. Scotland).
- **Technology**: .NET 8 / EF Core with PostgreSQL database.
- **Interfaces**: Internal domain repository interfaces and REST query endpoints.

#### Precedent Assembly & Template Engine
- **Responsibility**: Merges structured case metadata from PCMS Core with standardized OpenXML Word/PDF precedent templates to dynamically generate pleadings, contracts, missives, and legal forms.
- **Technology**: .NET 8 DocumentFormat.OpenXml engine with cached template definitions.
- **Interfaces**: RESTful endpoints (`/api/v1/precedents/assemble`) and asynchronous generation workers.

#### Dual-Jurisdiction Court Bundling & OCR Engine
- **Responsibility**: Executes multi-document court bundle collation, automated Bates stamping, interactive Table of Contents (TOC) hyperlinking, OCR extraction, PPE page counting for LGFS, and PDF/A compilation compliant with HMCTS, SCTS, and LAA practice directions.
- **Technology**: .NET BackgroundService / Python Celery workers utilizing headless PDF rendering engines (PdfSharp / Chromium) and Tesseract / Azure AI Document Intelligence.
- **Interfaces**: Consumes bundling task messages from Azure Service Bus / AWS SQS and emits real-time progress events via Redis Pub/Sub and WebSockets.

#### Outlook Ingestion & Telemetry Adapter
- **Responsibility**: Ingests email metadata, `.eml`/`.msg` files, and email attachments streamed from both Classic Outlook (Win32 VSTO) and New Outlook (Office.js) add-ins, executing de-duplication, predictive matter assignment, and telemetry logging for quarterly feature optimization.
- **Technology**: ASP.NET Core streaming endpoints with multipart form-data parsing, MIME type validation, and asynchronous telemetry queues.
- **Interfaces**: RESTful HTTPS endpoints (`/api/v1/ingest/outlook/...`).

#### Webhook Synchronization Listener
- **Responsibility**: Ingests Microsoft Graph change notifications (SharePoint webhooks) to detect external file modifications, metadata edits, and new versions.
- **Technology**: .NET 8 Minimal API endpoint backed by Azure Event Grid / SQS.
- **Interfaces**: Public HTTPS webhook receiver endpoint validated by Graph client secrets.

## Data Architecture

### Data Models
- **Document Reference**: Entity tracking logical document ID, matter ID, jurisdiction code (EW / SCT), document title, category, SRA / Law Society of Scotland retention class, SharePoint DriveItem ID, WebUrl, file size, MIME type, and SHA-256 hash.
- **Document Version**: Historical snapshot recording version number, SharePoint etag, modified timestamp, modifier fee-earner ID, change summary, and redline diff metadata.
- **Court Bundle Definition**: Specifies bundle sections, document ordering, Bates numbering formats (e.g., prefix conventions for SCTS / HMCTS), index styling, pagination layout, and compilation job state.
- **Precedent Template**: Entity managing base OpenXML templates, jurisdiction tags, placeholder token mappings, conditional clause rules, and category classification.
- **PPE Evidence Record**: Tracks prosecution evidence page metrics, electronic document checksums, served evidence indices, and LGFS compliance validation states for Crown Court cases.
- **Upload Session**: Tracks transient large-file upload tokens, byte chunk offsets, expiration timestamps, and target SharePoint drive paths.
- **OCR Text Index**: Searchable full-text extract linked to document version references for instant full-text case search across matter files.

### Data Flow
1. **Matter Folder Provisioning**: On `MatterCreated` event from PCMS Core, the service invokes Microsoft Graph API to create a dedicated SharePoint document library and subfolder structure tailored to the practice area and jurisdiction (e.g., Land Registry vs. Registers of Scotland).
2. **Direct Document Ingestion (Web & Dual Outlook)**: Fee earner initiates filing from PCMS web or Outlook (Classic/New); the service creates a Microsoft Graph chunked upload session and returns a direct upload URL; client streams binary directly to SharePoint; Graph webhook confirms completion to persist the `Document Reference`.
3. **Dynamic Precedent Assembly**: Fee earner triggers document creation; PCMS Core sends case variables; the Precedent Assembly Engine fetches the base OpenXML template, merges data bindings and jurisdiction-specific clauses, streams the generated document to SharePoint, and logs the new version pointer.
4. **Co-Authoring Launch**: Fee earner requests document edit; the service checks ethical wall authorization with PCMS Core, fetches a short-lived SharePoint WebUrl via Graph API, and launches Office 365 co-authoring.
5. **Court Bundle & PPE Assembly (HMCTS, SCTS & LGFS)**: User configures bundle parameters in UI; the service enqueues a job in Service Bus; worker containers pull source files from SharePoint, execute OCR, calculate PPE counts, apply jurisdiction-specific Bates numbering and hyperlinked TOC, compile compliant PDF/A, and save the artifact back to SharePoint.

### Storage Strategy
- **Primary Database**: Azure Database for PostgreSQL / Amazon RDS PostgreSQL (Multi-AZ Deployment) storing document references, version indexes, jurisdiction policies, precedent definitions, PPE records, bundle templates, and task states.
- **Caching**: Azure Cache for Redis / Amazon ElastiCache for Redis managing Graph API access tokens, upload session states, template token caches, worker queue locks, and real-time bundling progress.
- **File Storage**: Microsoft SharePoint Online Document Libraries via Microsoft Graph API for authoritative long-term binary persistence; transient Azure Blob / AWS S3 storage for temporary PDF bundle collation staging.

## API Design

### API Style
RESTful JSON APIs over HTTPS (TLS 1.3) for synchronous metadata, precedent drafting, and upload session operations; Asynchronous message queues (Service Bus / SQS) and WebSockets for long-running court bundling, PPE evidence analysis, and OCR jobs.

### Key Endpoints
- `POST /api/v1/workspaces/provision`: Provisions matter-specific document libraries in SharePoint Online with jurisdiction templates.
- `POST /api/v1/matters/{matterId}/documents/upload-session`: Initializes a direct chunked upload session for files >4MB.
- `POST /api/v1/precedents/assemble`: Merges matter parameters with an OpenXML template to dynamically assemble a legal precedent.
- `POST /api/v1/ingest/outlook/email`: Ingests email messages and attachments from Classic and New Outlook add-ins.
- `GET /api/v1/matters/{matterId}/documents`: Lists all document references with SharePoint sync and version status.
- `GET /api/v1/documents/{documentId}/open-url`: Generates a secure, time-limited Office 365 co-authoring URL.
- `POST /api/v1/matters/{matterId}/bundles`: Enqueues an electronic court bundle compilation job with HMCTS, SCTS, or LGFS PPE presets.
- `GET /api/v1/bundles/{bundleId}/status`: Returns compilation progress, OCR status, PPE page count, and artifact download link.
- `POST /api/v1/webhooks/graph-notifications`: Ingests and processes asynchronous SharePoint delta events.

### Authentication & Authorization
- **Authentication**: OAuth 2.0 / OpenID Connect integrated with the OneAdvanced Identity Platform and Microsoft Entra ID, utilizing Microsoft Graph On-Behalf-Of (OBO) flow and managed identity service principals.
- **Authorization**: Validates fee-earner JWT token claims against matter ethical wall scopes and practice-level permissions passed from PCMS Core before issuing document pointers, precedent templates, or upload sessions.

## Infrastructure

### Deployment Architecture
- **Cloud Provider & Region**: Microsoft Azure deployed in **UK South** (primary) and **UK West** (paired), or AWS **eu-west-2** (London), guaranteeing strict UK data residency and UK GDPR compliance.
- **Deployment Model**: Containerized microservices deployed via Azure Container Apps / AKS / AWS ECS Fargate, partitioned into interactive API containers, precedent engines, and dedicated background bundling/OCR workers.
- **Availability Target**: 99.99% uptime with multi-AZ container distribution and managed database auto-failover.

### Scaling Strategy
- **Horizontal**: API containers scale out from 2 to 10 instances based on HTTP request rate and CPU utilization (>70%).
- **Vertical**: PostgreSQL database configured with Provisioned IOPS SSD storage to handle high-concurrency document pointer lookups for 100+ to 450 concurrent fee earners.
- **Auto-scaling**: Bundling and precedent worker containers scale dynamically from 2 to 20 instances based on queue depth in Azure Service Bus / AWS SQS (trigger: >5 pending jobs).

### Monitoring & Observability
- **Logging**: Structured JSON logs collected via Azure Monitor / Application Insights, tracking Graph API HTTP response codes, precedent assembly durations, jurisdiction tags, and correlation IDs.
- **Metrics**: Graph API rate-limiting metrics (429 response frequency), average bundle assembly duration, OCR processing throughput, PPE analysis latency, and worker queue lag.
- **Alerting**: Real-time alerts for Graph API authentication errors, bundle generation failures, queue backlogs exceeding 10 minutes, and 429 throttling spikes.

## Security Architecture

### Security Layers
- **Network Security**: Private Virtual Network (VNet) with Private Endpoints for PostgreSQL, Redis, and internal service communication; public ingress protected by Azure Application Gateway WAF with TLS 1.3.
- **Identity & Least Privilege**: Managed Identities for Azure resources, fine-grained Microsoft Graph application permission scopes (`Files.ReadWrite.All`, `Sites.Selected`), and short-lived SAS/Graph tokens.
- **Data Protection & Encryption**: AES-256 encryption at rest for all database records, precedent templates, and temporary bundle staging; TLS 1.3 for all data in transit; Microsoft 365 native BitLocker encryption for SharePoint persistence.
- **Regulatory Governance & Compliance**: Enforces dual-jurisdiction SRA and Law Society of Scotland document retention schedules, immutable audit logging for every document access/export event, and automated legal hold flag enforcement.
