# BundleDocs Cloud API & OAuth2 Service

## Strategic Context
PCMS requires a secure, modular integration client to communicate with the BundleDocs Cloud API (REST v1). Legacy desktop solutions relied on local executable launches (`Process.Start`), which are unsupported and insecure in cloud web environments. Implementing an OAuth2 authentication service and HTTP REST client enables PCMS to authenticate and provision bundle containers directly in the cloud.

## Success Criteria
- Secure acquisition and automatic refresh of OAuth2 Bearer tokens from BundleDocs authorization endpoints.
- Successful creation of bundle containers and section structures via REST endpoints with response times under 1000ms.
- 100% test coverage for API failure, token expiration, and retry logic.

## Scope

### In Scope
- OAuth2 token acquisition, storage, and automated refresh cycle implementation.
- `BundleDocsCloudService` class handling `POST /api/v1/bundles` and `POST /api/v1/sections`.
- Environment-specific configuration schema in `appsettings.json` (ClientID, ClientSecret, ApiBaseUrl, AuthorizeUrl).
- Structured error handling and logging for HTTP 401, 403, 429, and 5xx responses.

### Out of Scope
- Direct local desktop application execution or Desktop Agent bridging (unsupported in web PCMS).
- Webhook listener for external bundle completion events (deferred to Phase 2).

## Acceptance Criteria
WHEN a bundling request is initiated, the BundleDocsCloudService SHALL validate the active OAuth2 Bearer token and refresh it IF expired before executing API calls.

WHEN bundle creation is triggered, the BundleDocsCloudService SHALL issue a POST request to `/api/v1/bundles` with title and matter code and receive valid `PartitionKey` and `RowKey` identifiers.

WHEN a bundle container is confirmed, the BundleDocsCloudService SHALL issue a POST request to `/api/v1/sections` to generate the default target section container.

IF the BundleDocs API returns an HTTP 401 Unauthorized response, THEN the BundleDocsCloudService SHALL attempt a single token refresh before returning a structured authentication error.

WHERE API rate limits (HTTP 429) or transient 5xx errors occur, the BundleDocsCloudService SHALL execute exponential backoff retry up to 3 attempts.

## Business Rules
- OAuth2 client credentials and tenant secrets must be encrypted at rest.
- Bundle titles must follow the standard PCMS naming convention: `PCMS Bundle - {MatterReference} - {yyyy-MM-dd}`.
- All outbound HTTP requests must enforce a 30-second timeout.

## Dependencies
- BundleDocs Cloud API v1 endpoint availability and OAuth2 client credentials.
- PCMS Core Configuration and KeyVault secrets provider.
