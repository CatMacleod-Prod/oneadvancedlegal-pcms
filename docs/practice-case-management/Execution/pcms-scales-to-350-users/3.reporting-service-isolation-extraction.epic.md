# Reporting Service Isolation & Extraction

## Strategic Context
Heavy reporting queries currently share the primary database connection pool and web server memory, causing database CPU spikes and user session timeouts during month-end billing and management reporting. Isolating reporting connections and extracting report generation behind a dedicated service ensures reporting traffic cannot degrade core fee-earner workflows.

## Success Criteria
- Zero interactive matter transaction failures or slowdowns during concurrent execution of heavy practice reports.
- Read-intent connection isolation and concurrency throttles deployed across all 147 standard reports.
- Standalone Reporting Service extracted behind `IReportProducer` interface.

## Scope

### In Scope
- Read-intent reporting connection routing, bounded concurrency limits, and temporary table cleanup (RPT-01).
- Definition of the `IReportProducer` contract and abstraction seam (RPT-02).
- Extraction of the report merge and generation engine into an isolated service (RPT-02).
- Batch parity testing across standard report suites.
- Reporting telemetry and execution duration monitoring.

### Out of Scope
- Full UI rewrite of the report designer or custom BI query builder (RPT-04).
- Adoption of third-party BI engines (Snowflake/PowerBI) for standard operational reporting.

## Acceptance Criteria
WHEN a user triggers a practice or financial report, the Reporting Service SHALL route all query traffic through read-intent connections with bounded concurrency.

WHERE an asynchronous report generation exceeds 10 seconds, the Application SHALL notify the user via background notification upon completion without blocking the UI.

IF the Reporting Service experiences high queue depth, THEN the System SHALL prioritize interactive user queries over background report generation tasks.

## Business Rules
- Interactive reporting concurrency must be throttled to prevent resource starvation on replica read nodes.
- Extracted reporting service must maintain bit-for-bit output parity with existing DevExpress report layouts.

## Dependencies
- Dedicated App Service Plan provisioning and DevExpress licensing confirmation (GATE-02).
- Architecture sign-off on the `IReportProducer` interface definition.
