# Dashboard Performance & Pre-Calculated Read Models

## Strategic Context
Dashboard widget loading currently executes heavy, un-cached SQL queries with multiple temp-table scans and correlated subqueries, consuming excessive database CPU and blocking interactive user threads. Implementing pre-calculated read models and completing the XML provider transition is required to reduce dashboard database load by over 90% and support 350-user concurrency.

## Success Criteria
- Dashboard load times achieve P95 ≤ 2 seconds across all standard widgets at 350 concurrent users.
- Database CPU consumption from dashboard queries reduced by ≥ 85%.
- 100% of dashboard views migrated onto the XML schema provider with legacy loading paths retired.

## Scope

### In Scope
- Migration of the final 2 dashboard views to the XML schema provider (DASH-01).
- Server-side entitlement and authorization checks on all dashboard data endpoints (DASH-02).
- Implementation of pre-calculated read models behind `IDashboardDataService` with scheduled refresh (DASH-03).
- Selective precomputation for high-cost tiles based on telemetry (DASH-04).
- Read model cache invalidation on write events and freshness telemetry.

### Out of Scope
- Full UX redesign of the analytics dashboard (deferred to future BI initiatives).
- Direct Snowflake/Data Lake integration for interactive operational dashboards.

## Acceptance Criteria
WHEN a fee earner navigates to any dashboard view, the Dashboard Service SHALL serve widget data from pre-calculated read models within 2 seconds.

WHERE widget data requires authorization filtering, the Dashboard Data Endpoint SHALL evaluate user permissions server-side before returning data.

IF a read model is stale or missing, THEN the Dashboard Data Service SHALL trigger background refresh while returning cached data or executing a bounded live fallback.

## Business Rules
- Dashboard read model staleness tolerance must not exceed 15 minutes for operational metrics.
- Read model calculation tasks must run during off-peak windows or on background worker threads without taking exclusive locks on transactional tables.

## Dependencies
- Product sign-off on the ≤15 minute data staleness policy (GATE-03).
- IaC deployment of background refresh worker infrastructure.
