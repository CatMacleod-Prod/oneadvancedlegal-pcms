# Horizontal Scaling & Multi-Instance Infrastructure

## Strategic Context
PCMS currently operates in a single web instance topology per tenant, creating a hard physical ceiling on concurrent memory, CPU, and thread availability. Validating horizontal scale-out across multiple Azure App Service instances and confirming Wisej session affinity behavior is the foundational enabler for reaching 350+ active concurrent users.

## Success Criteria
- Validated horizontal scale-out across 3+ Azure App Service instances with zero session drops.
- Terraform autoscale rules defined and automated based on CPU and memory thresholds.
- Zero state leaks or cross-tenant session bleed under multi-instance multi-tenant traffic.

## Scope

### In Scope
- Feasibility spike confirming App Service Plan scale-out capability (SCALE-01).
- Wisej WebSocket and HTTP session affinity (ARR Affinity / Application Gateway routing) validation under load.
- Terraform IaC automation for autoscale definitions and multi-instance deployment topologies (SCALE-02).
- Server runtime garbage collection (`gcServer`/`gcConcurrent`) multi-core optimization (XCUT-04).

### Out of Scope
- Re-architecting the Wisej stateful web framework into a purely stateless SPA.
- Multi-region geo-distributed database replication.

## Acceptance Criteria
WHEN traffic volume exceeds 70% CPU or 75% memory on active instances, the Infrastructure Layer SHALL provision additional App Service instances automatically.

WHILE an active fee-earner session is established, WHEN subsequent WebSocket or HTTP requests arrive, the Load Balancer SHALL route all traffic consistently to the session's host instance via session affinity.

IF an instance becomes unhealthy, THEN the Gateway SHALL redirect unauthenticated new connections to healthy instances while logging session termination diagnostics.

## Business Rules
- Session sticky routing must persist for the entire user session lifetime (idle timeout: 60 minutes).
- Scale-in actions must wait for active user draining before shutting down web instances.

## Dependencies
- Azure infrastructure allocation and non-prod performance testing environment access.
- Architecture review board confirmation on Wisej multi-instance compatibility (GATE-07).

## Open Questions
- Does the Redis backplane effectively sync session-adjacent caches across distributed instances?
