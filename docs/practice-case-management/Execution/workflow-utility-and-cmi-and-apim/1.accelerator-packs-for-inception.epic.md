# Core Legal Workflow Specifications & Flowable Packages

## Strategic Context

High-volume legal intake workflows—specifically Client Inception and Matter Inception—represent the primary operational gateway for law firm practices. By establishing validated specification files, multi-party review processes (Product, Services, and Customer), interactive customer demo rollouts, and automated Flowable BPMN application generation (Forms and Processes), PCMS provides production-ready, standardized intake automations that eliminate months of bespoke design, reduce onboarding friction, and accelerate firm-wide time to value. Additionally, enabling dynamic runtime contact selection for document generation within Flow eliminates the overhead of managing redundant static templates across variable contact counts.

## Success Criteria

* 100% specification sign-off achieved across core intake workflows: Client Inception and Matter Inception.
* Generated Flowable BPMN process applications and form schemas deploy successfully into the Flow tool and demo environments with zero runtime syntax errors.
* Collaborative review and sign-off cycle between Product, Services (CMI), and Customer completed within structured review windows.
* Interactive customer demo packages successfully provisioned and showcased to prospective and existing clients with guided walkthrough data.
* Clear delivery agreement and handoff established with Product and Services for Flow tool import and configuration.
* Document generation in Flow dynamically resolves and binds variable contacts without requiring multiple static templates or hardcoded workflows.

## Scope

### In Scope

* Specification file generation and formal multi-party review processes for:
  * Client Inception (KYC, eIDV, conflict checks, risk assessment, and client record setup)
  * Matter Inception (matter type validation, risk profiling, fee structure, billing arrangements, and team assignment)
* Customer-facing interactive demo package creation, including pre-populated sample client/matter data and guided evaluation scripts.
* Import and deployment package preparation for the Flow tool in coordination with Services (CMI).
* Dynamic contact selection for Flow document generation:
  * Retrieval of available contacts associated with a target entity (e.g., client, matter).
  * Presentation of available contacts in Flow form UI for single-contact selection at runtime.
  * Population and merging of selected contact details into target document templates.
  * Dynamic handling of variable or unknown contact counts per entity without template proliferation.
* Remove defect/enhancement blockers:
  * User Task Status Not Displayed Correctly in PCMS for Loop Scenarios under workflow tab
    * We have observed an issue where the status of User Tasks that are part of a Loop is not displayed correctly in PCMS. The status shown in PCMS does not reflect the actual execution state of the User Task.In contrast, Flow status is updated and displayed correctly for the same loop execution.
  * File uploads from Flow to PCMS

### Out of Scope

* Conveyancing workflows (Sale, Purchase, Re-mortgage, Transfer of Equity) — deferred to a dedicated future release.
* Commercial real estate, corporate acquisitions, and probate workflow specifications.
* Manual operational execution of client legal work (handled by fee earners within PCMS runtime).
* Direct end-customer legal advice or bespoke legal drafting rules.
* Multi-party simultaneous batch letter merging in a single task (single contact selection per document generation instance).

## Acceptance Criteria

WHEN workflow specifications are generated for Client Inception and Matter Inception, the Review Portal SHALL publish structured spec files for Product, Services, and Customer sign-off.

WHERE Product, Services, and Customer sign-off is completed on an inception specification, the Utility Build Engine SHALL generate the full Flowable BPMN application including all process diagrams and form definitions.

WHEN the generated application package is prepared, the Packaging Engine SHALL assemble all BPMN XML, form schemas, and demo configuration files into the agreed Flow tool import structure.

WHERE customer demo mode is enabled, the Inception Engine SHALL load pre-configured realistic client KYC, AML, conflict check, and matter risk assessment mock data into the walkthrough interface.

IF an inception specification is rejected or returned with notes during SME review, THEN the Specification Generator SHALL record the change items and produce an updated revision for re-review.

WHEN document generation is triggered within a Flow process for an entity (client or matter), the Flow Document Service SHALL retrieve the list of all available associated contacts.

WHEN presenting retrieved contacts in the Flow workflow task, the Flow Form UI SHALL display the contact list and allow the user to select one target contact regardless of the total contact count.

WHEN a contact is selected and document generation is executed, the Document Template Engine SHALL merge the selected contact's address and entity details into the generated document.

IF an entity has no linked contacts when document generation is initiated, THEN the Flow Form UI SHALL display a validation error requiring contact association before proceeding.

## Business Rules

* Flowable BPMN generation must not commence until formal sign-off is registered by Product and Services (CMI) leads.
* Delivery timelines for BPMN application generation and Flow tool configuration are subject to joint agreement between Product and Services.
* Client Inception must enforce mandatory identity verification (eIDV) and conflict check milestones before matter opening is permitted.
* Dynamic contact selection in Flow must support variable contact counts without requiring separate workflow tasks or branch paths per contact type.
* Document template population must resolve contact tokens dynamically from the user-selected contact record at runtime execution.

## Dependencies

* AI Workflow Generation Utility Pipeline (Epic 1) for spec generation and BPMN build.
* Product and Services (CMI) team alignment for sign-off and Flow tool import.
* Core PCMS case data dictionaries, contact entity models, and legal practice taxonomy definitions.
* PCMS Contact & Entity REST APIs for dynamic contact retrieval within Flow.
* Third-party eIDV/AML verification connectors for demo mock payloads.
