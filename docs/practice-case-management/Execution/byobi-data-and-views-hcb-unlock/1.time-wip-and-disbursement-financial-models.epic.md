# Time, WIP and Disbursement Financial Models

## Strategic Context
Mid-market UK legal practices require real-time matter-level visibility into recorded fee-earner time, WIP adjustments, unbilled disbursements, and grouped billed expenses to manage fee-earner realization and project profitability. Currently, extracting this financial data relies on legacy SQL Server user-defined functions (udf_TimeByMatterAdjustmentDate, udf_TimeByMatterByDate, udf_DisbsByMatter, udf_BilledDisbsByDisbGrouped), creating operational bottlenecks, slow query times, and an inability to connect modern business intelligence tools directly. Replicating these functions as native Snowflake views and DBT models with parameterized date cutoffs unlocks self-service analytics and eliminates legacy database load.

## Success Criteria
- 100% functional and mathematical parity between legacy time/disbursement UDF outputs and new Snowflake models across historical sample matter sets.
- Sub-second query response times for matter-level time and disbursement aggregates with date-cutoff parameters.
- Direct BI tool compatibility enabling ad-hoc queries without custom ETL scripts.

## Scope

### In Scope
- DBT model and Snowflake view replacement for `udf_TimeByMatterAdjustmentDate`.
- DBT model and Snowflake view replacement for `udf_TimeByMatterByDate`.
- DBT model and Snowflake view replacement for `udf_DisbsByMatter`.
- DBT model and Snowflake view replacement for `udf_BilledDisbsByDisbGrouped`.
- Standardized date-cutoff filtering parameters across all four time and disbursement models.

### Out of Scope
- Modifications to underlying transactional time recording tables in the PCMS core database (defer to core application roadmap).
- Real-time streaming ingestion pipelines (batch DBT scheduling applies).

## Acceptance Criteria
WHEN a downstream BI tool queries the matter time view with a date cutoff parameter, the Snowflake Time Model SHALL return all time entries and adjustments recorded on or before that date partitioned by matter.

WHEN an unbilled disbursement query executes against the disbursement model, the Snowflake Disbursement Model SHALL aggregate internal and external disbursements grouped by matter and disbursement type.

WHERE WIP adjustment records exist for a matter, the Time Adjustment Model SHALL apply debit and credit rate adjustments to calculate the net WIP balance accurately as of the cutoff date.

IF an invalid or future cutoff date parameter is provided, THEN the Snowflake model SHALL filter transactions up to current system timestamp without throwing execution errors.

## Business Rules
- Time entries must preserve fee-earner hourly rate baselines alongside matter-specific billing overrides.
- Disbursement groupings must align with standard UK legal accounting classifications (Counsel fees, court fees, search fees, general expenses).
- All date filtering logic must strictly use UTC timestamps truncated to end-of-day for historical cutoff reporting.

## Dependencies
- IPS-574 core aggregating transformation engine support in Snowflake.
- Replicated raw time and disbursement tables synced to the Snowflake analytical schema.
